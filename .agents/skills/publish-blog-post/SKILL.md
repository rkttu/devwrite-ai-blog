# 블로그 글 전체 발행

## 역할과 라우팅

이 스킬은 전체 발행 요청에서 다음 하위 스킬을 순서대로 조정합니다.

1. 콘텐츠 작성, 리뷰, 탈고: `$prepare-blog-post`
2. 커밋, 푸시, Actions 감시, 운영 URL 확인: `$deploy-blog-post`
3. 닷넷데브 게시 초안과 브라우저 인계: `$publish-blog-to-dotnetdev`
4. LinkedIn 문안과 공유 화면 인계: `$share-blog-on-linkedin`

사용자가 특정 단계만 요청하면 전체 흐름을 시작하지 않고 해당 하위 스킬만 사용합니다. 예를 들어 글 리뷰에는 `$review-draft`, 번역에는 `$translate-post`, 배포 재확인에는 `$deploy-blog-post`를 사용합니다.

## 시작 상태 확인

대상 slug와 요청 범위를 확정하고 다음 상태를 현재 저장소와 외부 서비스에서 다시 계산합니다.

- 콘텐츠 파일과 세 언어 준비 상태
- `draft` 값과 로컬 검증 결과
- 대상 커밋과 원격 반영 여부
- 해당 SHA의 GitHub Actions 실행
- 운영 slug URL 반영 여부
- canonical URL로 찾은 기존 닷넷데브 토픽
- 사용자가 알려 준 기존 LinkedIn 게시 여부

이전 대화의 진행 상태만 믿지 않습니다. 확인 가능한 상태는 다시 조회하고 LinkedIn처럼 정책상 조회하지 않는 상태는 사용자에게 확인합니다.

## 단계 게이트

콘텐츠 준비와 로컬 검증이 실패하면 커밋하지 않습니다. 푸시가 현재 요청에 명시되어 있지 않거나 사용자가 금지했다면 커밋 이후 중단합니다. 이미 푸시 승인이 명시된 전체 발행 요청에는 같은 승인을 반복해서 묻지 않습니다.

GitHub Actions 실행과 운영 HTML 검증을 모두 통과하기 전에는 외부 채널 게시를 시작하지 않습니다. 새 글의 Open Graph 메타데이터와 대표 이미지도 확인해 외부 공유 미리보기 오류를 줄입니다.

닷넷데브 단계에서는 기존 토픽 중복 검색과 본문 미리보기를 거칩니다. `disc draft`가 브라우저를 열어도 사용자가 발행을 확인하기 전에는 완료로 기록하지 않습니다.

LinkedIn 단계에서는 승인된 문안을 클립보드로 전달하고 공유 화면만 엽니다. 브라우저 입력과 게시 버튼을 자동화하지 않으며 사용자의 게시 확인 전에는 완료로 기록하지 않습니다.

## 실패와 재개

배포 실패는 이후 모든 단계를 중단합니다. 원인을 수정해 새 커밋을 푸시했다면 새 SHA의 Actions 실행과 운영 URL을 다시 검증합니다.

닷넷데브 또는 LinkedIn 단계가 실패하거나 사용자의 수동 작업을 기다리는 경우에는 이미 완료한 블로그 배포를 되돌리지 않습니다. 현재 상태와 재개할 하위 스킬을 보고하고 다음 외부 채널로 계속할지는 사용자에게 확인합니다.

재개 실행에서는 이미 완료한 단계를 반복하지 않습니다. 닷넷데브는 canonical URL과 제목 검색으로 중복을 확인합니다. LinkedIn 공유 화면을 이전에 열었다면 사용자가 게시 여부를 확인하기 전까지 다시 열지 않습니다.

## 완료 보고

다음 항목을 서로 구분해 보고합니다.

- 글 준비와 검증 결과
- 콘텐츠 커밋 SHA와 푸시 여부
- GitHub Actions 실행 URL과 결론
- 세 언어 운영 URL 확인 결과
- 닷넷데브의 초안 인계 또는 사용자 발행 확인 상태
- LinkedIn의 공유 화면 인계 또는 사용자 발행 확인 상태

브라우저 인계 상태를 게시 완료라고 표현하지 않습니다. 블로그 URL을 source of truth로 유지하며 외부 게시물 본문을 별도의 원본으로 취급하지 않습니다.
