# LinkedIn 블로그 글 공유

## 자동화 경계

이 스킬은 문안 생성, 사용자 미리보기, 클립보드 복사, LinkedIn 공유 화면 열기까지 수행합니다. LinkedIn 웹사이트에서 자동 입력, 클릭, 게시, 스크래핑을 수행하지 않습니다. 사용자가 `Post` 버튼을 누르고 결과를 확인합니다.

LinkedIn은 제3자 도구가 웹사이트 활동을 자동화하는 행위를 금지합니다. 현재 정책은 [LinkedIn 자동 활동 안내](https://www.linkedin.com/help/linkedin/answer/a1340567/automated-activity-on-linkedin?lang=en)에서 확인합니다.

## 원문과 사전 확인

한국어 운영 URL `https://devwrite.ai/ko/posts/<slug>/`을 source of truth로 사용합니다. 먼저 `$deploy-blog-post` 결과 또는 직접 확인을 통해 HTTP 200, 제목, canonical URL, Open Graph 메타데이터, 대표 이미지 응답을 검증합니다. 운영 반영을 확인하지 못하면 공유 화면을 열지 않습니다.

같은 글을 이미 LinkedIn에 올렸는지 사용자에게 확인합니다. LinkedIn 계정이나 프로필을 스크래핑해 중복 여부를 추정하지 않습니다. 이전 실행이 공유 화면을 연 상태에서 끝났다면 다시 열기 전에 게시 여부를 묻습니다.

## 문안 작성

문안을 작성하기 전에 `writing-style-guide.md` 전체를 읽습니다. 사용자가 별도 문체를 지정하지 않았다면 소셜 게시글에 해당하는 존댓말 구어체를 사용하고 산출물의 길이와 구조에 맞는 적용 등급을 선택합니다.

한국어 원문에서 확인한 사실과 결론만 사용합니다. 다음 구조를 기본으로 삼되 글의 성격에 맞춰 조정합니다.

1. 핵심 키워드와 결론을 담은 첫 문장
2. 글에서 다룬 문제나 배경
3. 독자가 확인할 수 있는 핵심 내용 두세 가지
4. 필요한 경우의 짧은 질문 또는 의견 요청
5. canonical URL
6. 마지막 줄의 해시태그

첫 문장을 `새 글을 작성했습니다` 같은 게시 알림으로 시작하지 않습니다. 첫 줄에 해시태그를 두지 않습니다. 전체 문안은 LinkedIn 일반 포스트의 3,000자 제한을 넘지 않습니다. 원문에 없는 경험, 성과, 수치, 감정, 관계를 만들지 않습니다.

해시태그는 front matter의 태그와 본문 주제를 바탕으로 세 개에서 다섯 개를 고릅니다. 핵심 기술, 독자 범주, 글의 맥락을 우선하고 중복되거나 지나치게 넓은 태그를 제외합니다. 공백과 구두점을 제거하고 알려진 기술명은 다음과 같이 정규화합니다.

- `.NET`에서 `#dotnet`
- `C#`에서 `#csharp`
- `GitHub Actions`에서 `#GitHubActions`

## 사용자 인계

브라우저를 열기 전에 문안 전체, 해시태그, canonical URL을 사용자에게 보여 주고 수정을 반영합니다. 승인된 문안을 현재 운영체제의 클립보드 도구로 복사합니다. 도구가 없다면 설치하지 않고 추적되지 않는 임시 텍스트 파일 경로를 제공합니다.

검증한 블로그 페이지의 LinkedIn 공유 링크를 기본 브라우저로 엽니다. 공유 링크가 동작하지 않으면 LinkedIn의 `Start a post` 화면과 canonical URL을 안내합니다. URL 파라미터가 본문과 해시태그를 채운다고 가정하지 않으며 사용자가 클립보드 내용을 붙여넣고 최종 문체를 다듬도록 안내합니다.

사용자가 게시 완료를 확인하기 전에는 LinkedIn 게시를 완료로 보고하지 않습니다. 가능하면 사용자가 제공한 게시물 URL을 최종 보고에 포함합니다.
