# 블로그 초안 리뷰

## 검토 자료

대상 slug의 한국어, 영어, 일본어 파일과 관련 이미지를 확인합니다. `CLAUDE.md`, `.github/copilot-instructions.md`, `writing-style-guide.md` 전체를 읽습니다. 한국어 원문은 완결된 배포 문서에 해당하는 규칙과 탈고 체크리스트로 검토하고 영어와 일본어는 각 언어의 자연스러운 기술 문체를 기준으로 검토합니다.

변경 가능성이 있는 사실, 외부 문서, 제품 버전, API는 공식 1차 출처로 다시 확인합니다. 확인하지 못한 정보는 단정하지 않습니다.

## 검토 항목

다음 순서로 발견 사항을 정리합니다.

1. 발행을 막는 사실 오류, 깨진 명령, 누락된 필수 메타데이터
2. 세 언어의 의미, slug, `translationKey`, 날짜, 이미지 경로 불일치
3. 출처, 라이선스, 내부 링크, 코드 블록 문제
4. 문장 구조, 제목, `description`, `tldr`, 대체 텍스트 개선점

가능하면 파일과 줄을 지정하고 문제의 영향과 수정 방향을 설명합니다. 문제가 없다면 확인한 범위와 남은 위험을 적습니다.

## 자동 검증

리뷰 과정에서 다음 검증을 실행합니다.

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_translations.py
python3 scripts/check_asset_sizes.py
```

사용자가 리뷰만 요청했다면 파일을 수정하지 않습니다. 수정과 탈고까지 요청한 경우에만 발견 사항을 반영하고 검증을 다시 실행합니다. 커밋, 푸시, 발행은 별도 요청 범위입니다.
